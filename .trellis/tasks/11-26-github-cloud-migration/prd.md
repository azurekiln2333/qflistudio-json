# JSON GitHub migration

## Requirements

- Preserve all JSON source and durable Trellis progress in GitHub.
- Exclude generated files, caches, installers, private keys and machine signing configuration.
- Review every local and remote branch. Integrate accepted work into main.
- Clone the project with its declared core dependency on another PC.
- Execute all builds, tests, analyzers and dependency installation on GitHub.
- Provide Windows, Linux, macOS, iOS, Android and OHOS package workflows.
- Retain bounded cloud artifacts for Flutter and native intermediates.
- Pull the canonical GitHub repository into the target workspace.
- Compare source and target tracked trees and confirm clean worktrees.
- Deliver cleanup instructions and a Herdr handoff to the target Codex.

## Acceptance

- GitHub main, source main and target main identify the same reviewed tree.
- Durable tasks, specifications and journals are tracked.
- No credentials or generated build output enter the published tree.
- Every local or remote branch has a recorded integration disposition.
- Cloud jobs and artifacts are checked against the exact commit.
- Unsigned packages do not count as signed installable releases.
- Missing secrets, SDKs or runner access remain explicit blockers.
- Historical product acceptance stays separate from migration acceptance.
- No local build, test, analyzer, package resolution or SDK installation runs.
- Cleanup never deletes source, secrets or shared WSL data without an exact reviewed scope.
